# AAPESH 2.0 - Windows Release

**Version:** 2.0.0  
**Platform:** Windows x64  
**Release type:** Initial Windows desktop release

## What's new

- Native AAPESH desktop shell with a custom application icon, Start Menu entry, and optional Desktop shortcut.
- Bundled FastAPI/Python runtime; users do not need to install Python.
- Backend binds to loopback only, selects and remembers an available local port, starts with the app, and shuts down with it.
- Production frontend is served from the local backend so existing `/api` calls and navigation continue to work.
- Playlists, liked songs, listening history, search data, and YTMusic credential files are stored under `%APPDATA%\AAPESH`, outside the installation and temporary portable extraction directories.
- NSIS installer supports choosing an installation location. Uninstall preserves user data.
- Portable executable is also provided.

## Installation

1. Download `AAPESH-Setup-x64.exe`.
2. Run the installer and choose an installation folder if desired.
3. Launch AAPESH from the Start Menu or Desktop shortcut.

Alternatively, run `AAPESH-Portable-x64.exe`. The portable build still stores persistent user data in `%APPDATA%\AAPESH`.

`SHA256SUMS.txt` contains SHA-256 checksums for both executables.

## System requirements

- Windows 10 or Windows 11, 64-bit (x64).
- Internet access for music search, artwork, lyrics services, and YouTube playback.
- Python and Node.js are not required.

The release packaging smoke test runs on a Windows x64 GitHub Actions runner. Windows 10 is a supported Electron target, but the install/uninstall automation is run on the current Windows runner image rather than every Windows 10 build.

## Known limitations

- Music playback is provided by YouTube's embedded player and requires an available network connection and playable YouTube content. AAPESH does not download or provide offline music files.
- YouTube Music account synchronization requires valid YTMusic OAuth/browser credentials. Credentials are not bundled; the existing setup instructions currently refer to the Python development helper, so desktop users may need to configure credentials manually. Public search and playback remain available without account credentials.
- The application is not code-signed in this initial build. Windows SmartScreen may show an unknown-publisher warning.
- SQLite initialization is additive and preserves existing rows. The project does not yet have an Alembic migration history; future schema changes must introduce and test versioned migrations before release.
- Windows media-session metadata and global media-key integration are not included in this initial release.
